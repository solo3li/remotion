# ADR 0021 — 员工工位；以及本机并行冲突控制

- 日期：2026-08-21
- 状态：已拍板（项目所有者）
- 依赖：[ADR 0019](0019-dsh-as-agent-runtime.md)（dsh 运行时）、[ADR 0020](0020-employee-is-agent-and-interaction-model.md)（员工就是 agent）
- 继承：[ADR 0017](0017-resource-aware-workforce-scheduler.md) 的资源租约模型（**照搬，不重造**）
- 继续有效：[ADR 0005](0005-hermes-poc-safety-findings.md)（绝对路径 / UnitPulse 隔离）

## 起因

三端同步（手机 / Mac / Windows）引出两个真问题，由项目所有者提出：

> "多个 agent 在同一个电脑操作 会有问题，一个 agent 在多个电脑操作，也会有问题？"

其提议是"规定一个 agent 只能在一个端工作"。方向正确，但原始表述把**员工**和**设备**绑在一起。ADR 0017 已经记过正确的切分：

> "逻辑员工数、物理执行槽和独占设备**不是同一维度**"

## 决策一：员工在入职时确定「工位」，之后不可随意变更

`agents.workstation` 二选一，招聘时定：

| | **云员工** | **本机员工** |
|---|---|---|
| 运行时跑在哪 | 服务端 | 绑定的那一台设备 |
| session 账本（深层记忆） | 服务端 | **那台设备本地** |
| 聊天记录 / 公司事实 | API（三端同步） | API（三端同步） |
| 能动老板的项目文件 | ❌ | ✅ 仅限该设备上的 |
| 上班时间 | 7×24 | 该设备在线时 |
| 手机上 | 可对话 | 可对话；离线时显示「不在工位」 |

推论（写死）：

1. **工位不可随意变更。** 改工位 = 一次显式「调岗」，必须迁移 session 账本。这是防 split brain 的唯一机制 —— 允许自由漂移就等于允许同一员工存在两份记忆。
2. **一个本机员工只住一台设备**，只能动那台设备上的文件。想让同一角色在 Mac 和 Windows 都干活 → **招两个员工**，各有各的记忆。这正是项目所有者直觉的正确形式。
3. **聊天记录永远在 API**，这是三端同步的地基。深层记忆留在员工住的地方（对本机员工而言这是隐私优势，不是缺陷）。
4. **本机员工离线时**，发给他的消息进 API 队列，设备上线后送达。群里显示其在岗状态。

因此项目所有者那条"一个 agent 只能在一个端工作"**成立**，但它是**入职时选定的员工属性**，不是全局调度限制。

## 决策二：「地方」= (设备, 绝对路径)，设备之间不同步

一个可被任务指向的**地方**是 `(device_id, absolute_path)`。

Mac 上的 `~/code/myapp` 与 Windows 上的 `D:\code\myapp` 是**两个不同的地方**，即使代码内容相同。

**我们从不试图同步设备。** 不假装两个地方是同一个东西，所谓"Mac 和 Windows 同步会有问题"就不存在。真需要两边内容一致，那是 git 的职责，不是 AgentPulse 的。

## 决策三：本机并行冲突控制 —— 照搬 ADR 0017

不重新设计。沿用 `resource_leases`：资源类型 `project_write` / `git_worktree` / `local_terminal` / `computer_use` / `browser_context` / `model` / `server_hermes`（改名 `server_runtime`），模式 `shared` | `exclusive`。

三条规则：

1. **每员工同一时刻只有一个前台 Run。** 保留人类式的上下文连续性，也顺带保证"一个员工不可能同时在两处动手"。
2. **写任务各自一个独立 git worktree。** git worktree 就是为此设计的 —— N 份独立检出、零冲突。
3. **真独占的资源排队**：`computer_use`（一台机器只有一套鼠标键盘）、`local_terminal`、非 git 目录的 `project_write`（无法 worktree，只能严格一次一个）。

于是：**多员工同一台机器 → 可以**（各自 worktree + 独占资源排队）；**一员工多台机器 → 不发生**（本机员工只住一台；云员工不碰设备）。

## 由此收缩 P1：不要服务器

既然本机员工在 P1 就能动文件，而第一个用户是项目所有者本人、在 macOS 上：

**P1 只做本机员工，完全不要服务端。** API（FastAPI）跑在老板自己的 Mac 上，Electron 连 localhost，手机 PWA 连该 Mac 的局域网地址。三端同步照样得到真实验证，但省掉旧版卡最久的一整块（Vercel / Supabase / Oracle / DNS / 多租户）。

代价与诚实说法：P1 的 7×24 是"你电脑开着的时候上班"。这对 v0.1.0、单用户、自己的机器是可接受且可解释的。

**云员工与 7×24 推到 P2**（需要服务器）。届时 `workstation` 字段已在，加一个枚举值即可，不动模型。
