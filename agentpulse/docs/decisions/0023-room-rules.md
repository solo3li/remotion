# ADR 0023 — 房间规则；以及「何时算对齐」交给员工

- 日期：2026-08-22
- 状态：已实现
- 依赖：[ADR 0020](0020-employee-is-agent-and-interaction-model.md)（员工就是 agent / 房间是基础设施）、[ADR 0022](0022-human-bridge.md)（人机桥）
- 收窄：[ADR 0002](0002-self-built-group-discussion.md) —— 结论仍然成立（讨论层自研），但范围比旧版小得多

## 决策一：群的三条规则

按北极星推出来，非拍脑袋：

1. **员工也能拉人进群。** 只有老板能拉，老板就得知道该拉谁 —— 那是管理员工作，违反北极星①「用户是老板，不是系统管理员」。员工发现"这事得让懂 X 的人来"就该能拉同事进来。**但拉人是群里可见事件**（谁拉了谁、为什么），不是静默的。
2. **员工之间可以私聊、不带老板；老板随时可翻看。** 每句话都过老板，老板就是瓶颈。**这条不需要任何新代码** —— 私聊 = 参与者为 2 的房间（ADR 0020），所以"员工私聊"只是一个员工建的、老板不在其中的房间。
3. **不区分群类型。** 不做项目群/部门群之分，群就是群，可归档。真需要区分时再说（YAGNI）。

## 决策二：「何时算讨论对齐」不由我们判断，交给员工

旧版：我们的代码检测收敛（`check_convergence`）→ 我们生成 brief（含起草 prompt、非法 JSON 的修复 prompt、`validate_work_items`）→ 老板在卡片上确认。

新版：**员工自己觉得对齐了，就调 `ask_user_question` 带 `plan-review` intent 请老板拍板**（ADR 0020 决定 plan-review 取代 brief 对象，ADR 0022 打通了这条链）。

这么改的理由不是省代码，是**北极星②说「Agent 要像人」** —— 人不需要外部程序判定"你们聊明白了没"，是当事人自己觉得清楚了就去请示。省代码是副产品。

后果：`app/rooms.py` **210 行**，而旧版 `discussion.py` 是 1,247 行。差额里最大的一块就是被 plan-review 吃掉的 brief 机制。

房间只保证两件事：讨论能进行、**讨论能停下**。停止条件三个，都是显式事件不是静默 break：

| reason | 触发 | 为什么要有 |
|---|---|---|
| `no_speaker` | 选不出发言人 | 讨论自然结束 |
| `max_turns` | 到硬上限（默认 12） | 兜住"没人主动收敛"的无限讨论 |
| `no_progress` | 员工返回空话 | 别空转烧 token |

## 决策三：P1 不用模型选发言人

发言人解析是三级 fallback：**待回应的 @提及 → 模型选 → round-robin**。但 `pick` 是**可选注入**，**P1 传 `None`** —— 只用 @提及 + round-robin。

理由：三人群里 round-robin 完全够用；省掉每轮一次模型调用；且绕开了"选发言人算不算员工输出、能不能不走 dsh"这个 ADR 0019 边界问题。等 round-robin 明显选错了再接。

## 编排层纪律（旧版在这里翻过车）

`app/rooms.py` **不 import HTTP / DB / dsh 任何东西**。执行一轮、选人、读写消息全部由调用方注入。唯一的接缝是 `app/runtime/employee_turn.py`。

这条不是洁癖：旧版 TD-02 出过事故 —— 路由层手写了一份重复的讨论循环，正确的编排函数当死码挂了两周才被发现。**编排逻辑只有一份，且可纯函数测试。**

## 验证

- `tests/test_rooms.py` —— **19 passed，0.02s**，纯函数 / 假执行器，不起进程不花钱。覆盖：中文无空格分词下的 @提及（`@阿伦你看下` 只匹配阿伦）、模型编了不存在的 id、老板永不被选为发言人、回复里的 @提及能盖过模型选择、三个停止条件。
- `tests/test_room_e2e.py` —— **1 passed，74.85s**，`DSH_E2E=1`。两个**真** dsh 员工进程在一个房间里各说一轮：round-robin 轮到两人各一次；人格真隔离（阿伦只认 `W-CONTENT`、阿哲只认 `W-DATA`，且阿伦没串到阿哲的工号）；第二个人看得到第一个人说了什么（共享 transcript）。

这是「员工就是 agent、平级同事」第一次真跑。

## 员工拉人：已实现并真跑通（2026-08-23）

决策一里"员工也能拉人"现在有代码了。**走 `ctx.tools` 注册一个公司自己的工具，不走 MCP** ——
`dsh-mcp` 不在 bundled runtime 里（[ADR 0019](0019-dsh-as-agent-runtime.md)），而我们的人机桥
本来就是 Cordis 插件，插件能直接注册工具。这条路顺带成了「公司工具」的样板。

工具是 `pull_in_colleague(colleague, reason)`。API 的 `invite` 现在按名字解析，**名字错时报错带上现有名单** ——
实测中员工正是靠这个自己纠正过来的（它先拉失败，把名单要过去，再重试成功）。

真跑结果：群里只有老板和产品经理，老板说"官网要重做视觉还要落成代码，你自己判断该叫谁进来"，
产品经理**先问清了四件事**（守它人格里"范围不清先问"那条），拿到回答后拉了两个人，理由都留在群里：

```
[system] 产品经理 把 设计 拉进来了：官网首页按品牌规范重做视觉，需要设计出稿。
[system] 产品经理 把 前端 拉进来了：视觉定稿后要落成代码，需要前端评估并排期。
```

### 树外 Cordis 插件的三个硬约束（都是实测撞出来的）

1. **`parameters` 必须是完整的 JSON Schema**，不是 `name → schema` 的映射。dsh 仓库里的例子写成映射，
   是因为它们过了 `defineTool()` 规范化。写成映射的后果很隐蔽：插件正常加载，但生成出的 function schema
   是 `type: null`，**DeepSeek 拒掉整个 Run，而报错只出现在 `turn/end` 里**，加载阶段一切正常。
2. **`import` 不到 dsh 自己的包。** bare specifier 从**导入文件所在位置**解析，Node 的向上查找走不到
   打包二进制的 node_modules。所以 `defineTool` 用不了，得自己写出它生成的形状。
3. **output schema 里 `required` 要用数组**，不能写成属性上的 `required: true`。
   bundled runtime（rc7）的校验器不接受后者 —— 而 repo main 的源码就是那么写的，**版本契约不一致**。

## 一个房间同一时刻只跑一场讨论

真跑时连发两句话，两场讨论并发跑：员工互相盖话、老板收到两组几乎一样的提问、回答重复落进 transcript。
现在第二句只进 transcript（在跑的那场下一轮自然会看到它），不额外起一场。
