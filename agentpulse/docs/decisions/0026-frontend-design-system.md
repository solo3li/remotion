# ADR 0026 — 前端：一套 React 撑三端，设计规范落纸

- 日期：2026-08-22
- 状态：已实现（浏览器实测）
- 依赖：[ADR 0020](0020-employee-is-agent-and-interaction-model.md)（员工就是 agent / 交互是同事对话）、[ADR 0021](0021-employee-workstation-and-resource-leases.md)（工位 / 三端）、[ADR 0025](0025-http-layer.md)（HTTP + SSE）
- 规范文件：根目录 [PRODUCT.md](../../PRODUCT.md)（方向 / 反参照）、[DESIGN.md](../../DESIGN.md)（token / 排版 / 布局）

## 决策一：一套 React（Vite），Mac 包 Electron、手机装 PWA

不为每端写一套。`apps/app` 是唯一的界面代码，响应式是**结构性的**（< 760px 折成单栏 + 返回导航），不是流体字号 —— 产品 UI 在固定 DPI 下看，流体标题在侧栏里只会更糟。

## 决策二：三条由架构推出来的界面决定

这三条不是审美偏好，是前面的 ADR 逼出来的：

1. **房间和人在同一个列表。** 私聊 = 参与者为 2 的房间（ADR 0020），所以人**就是**房间。不做「群 / 人」两个 tab，也不做 `Agents / Humans / Groups` 筛选。
2. **没有模态框。** 问答和拍板是 transcript 里的一条（ADR 0020），不是弹窗。整个界面零 modal。
3. **员工用字形标识，不用头像。** 员工是 agent，不假装是人；真正的身份信号是**在不在工位**（ADR 0021），所以每个员工行带在场点 + 工位一句话。

## 决策三：反参照实地看过，不是空喊

项目所有者点了三个反参照：管理后台 / cumora / 玩具感。cumora 的界面**下载截图看过**，逐条对照走开：

| cumora | 我们 | 依据 |
|---|---|---|
| AI agent 配真人照片头像 | 字形单元格 | 员工是 agent |
| 蓝色聊天气泡 | 平铺记录行，密度优先 | Linear 参照 + transcript 是账本 |
| 三栏 + Agents/Humans/Groups 筛选 | 两栏，房间和人一个列表 | ADR 0020 |
| 软阴影 / 大圆角 / 玻璃感 | 1px 实线 / 克制圆角 | 反参照「玩具感」 |

## 浏览器实测抓到的三件事

界面不是"写完就算"，起真后端 + 真数据在浏览器里走了一遍，抓到三个问题，其中两个是**产品/后端的真 bug**：

1. **答完之后卡片整个消失，老板不知道自己答了什么。**
   修法不是保住前端本地 state，而是**让回答变成 transcript 里老板的一条消息** —— ADR 0020 本来就写着"问答和拍板是消息"。这样决策进记录，且只有一个真相源。后端 `/asks/{id}/answer` 现在会 append 一条消息，前端删掉了本地翻面逻辑。
2. **发言顺序不确定。** `load_members` 按 `(joined_at, member_id)` 排序，而 `joined_at` 只到秒级 —— 同一秒进群的人并列，实际顺序落到随机 uuid 上，导致 round-robin 的第一发言人每次运行都不一样。改按 rowid（插入序）；`invite` 从 `INSERT OR REPLACE` 改成 `ON CONFLICT`，因为前者删了重插会分新 rowid、把人挪到队尾。
3. 员工行把设备名说了两遍（在场标签 + 工位行），挤到换行。在场标签收短。

另外查证了一件**不是** bug 的事：手机截图里按钮看着像填了底色，读计算样式确认底色是白的 —— 触摸模拟的残留状态，没动代码。

## 对比度：量过，不是估过

两次自写的对比度检查都是错的（第一次用正则把 `oklch(0.2 0.01 250)` 当 RGB 三个数解析；第二次读 canvas 的 `fillStyle` 回读值，对 oklch 是原样返回）。**正确做法是把颜色画到 canvas 上读像素** —— 浏览器自己做色彩空间转换。

最终 22 项（11 对 × 明暗两套）**全过、零 FAIL**。过程中改掉一个真缺陷：浅色下选中房间的名字压在选中态底色上只有 4.28，压暗主色 + 提亮 wash 到 4.93。

## 验证

- `npx tsc -b` 干净，`npm run build` 通过（CSS 12.19 kB / JS 154.80 kB，gzip 后 3.16 + 50.27 kB）。
- 浏览器：桌面明/暗、375×812 手机三档都看过；控制台零报错。
- 真点了一次答题，答案变成 transcript 里的消息、侧栏计数递减、房间预览跟着更新。
- 后端 **53 passed**（含两条新测试盯"回答落成消息"、两条盯成员顺序确定性）。

## 第二轮：把创建入口补上，又抓到三个真 bug

界面原先**没有任何入口能创建东西** —— 这是它看起来不完整的真正原因。补了招人（工位在这里定死）、开房间、拉人进群三个入口，全部**内联展开，不用模态框**。

然后真走了一遍「空公司 → 招人 → 开房间 → 说话 → 员工提问」，抓到：

1. **桥问不到人：`ask_user_question` 一直 HTTP 400。**
   桥只回传 `session_id`，API 靠 `agents.session_id` 反查员工 —— 但那一列从来没被写入过，而且这是鸡生蛋：ask 发生在 Run 进行中，那时 session id 还没落库。修法是**把 `agent_id` 和 `conversation_id` 直接注入给插件**（走 cordis config + 环境变量），session 反查降级成兜底。同时接上 `remember_session`，让下一轮能续跑。
   实测确认：修完员工真的调了 `ask_user_question`，两个结构化问题带选项和说明，`conversation_id` 正确，卡片在房间里渲染出来。
2. **在 Mac 上招人，手机看不到。** SSE 处理只对 `ask*` 前缀的事件刷新列表，漏了 `hired` / `room_opened`。改成默认刷新，不按事件名白名单 —— 三端同源就是这么漏掉的。
3. **进程重启会挂死。** uvicorn 优雅关闭会一直等后台讨论任务，而那个任务可能正阻塞在 30 分钟的桥等待上：日志停在 `Waiting for background tasks to complete`，旧进程占着端口不放，新进程起不来。现在 lifespan 会取消在飞任务并唤醒所有桥等待者（`AskBus.cancel_all` 我早就写了、但一直没接上）。**实测：讨论在跑时 SIGTERM，1 秒内干净退出。**

顺带修的：归档房间仍列在侧栏；`RunContext` 里我把带默认值的字段插到了没默认值的前面（dataclass 报错，而且我改完没先跑测试就去起服务，白等了七分钟）。

写测试时也犯了一个值得记的错：断言用 `"_discuss" in repr(task)` 找残留任务，结果把**测试函数自己**匹配进去了（函数名叫 `..._discussions`）。改成断言真实行为 —— 员工那轮是否收到 `CancelledError`。
