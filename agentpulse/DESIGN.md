# DESIGN.md — AgentPulse

## Theme

**明暗两套，跟随系统。**（PRODUCT.md：白天在 Mac 干活、夜里只有屏幕亮着。）

情绪句：*凌晨的一人办公室 —— 屋里只有屏幕的光，同事们还在各自的工位上转着。* 冷静、有值守感，不喧哗。

**色彩策略：Restrained**（Product register 的底线）。主色只用于当前选中、主操作和状态指示，绝不当装饰。

## Color (OKLCH)

底色遵循「情绪住在品牌色和字体里，不住在表面上」—— 浅色是**纯白**，深色是**纯中性近黑**（chroma 恰好 0）。把暖意/冷意同时放进主色和底色是 AI 的通病。

| 角色 | Light | Dark | 用在哪 |
|---|---|---|---|
| `bg` | `oklch(1 0 0)` | `oklch(0.09 0 0)` | 页面底 |
| `panel` | `oklch(0.975 0.002 250)` | `oklch(0.13 0.004 250)` | 侧栏/工具条（第二层中性，微偏主色相） |
| `line` | `oklch(0.905 0.004 250)` | `oklch(0.24 0.006 250)` | 1px 实线分隔（不用阴影分层） |
| `ink` | `oklch(0.20 0.01 250)` | `oklch(0.95 0.004 250)` | 正文 |
| `ink-2` | `oklch(0.50 0.012 250)` | `oklch(0.68 0.01 250)` | 次要文字（已核对 ≥4.5:1） |
| `primary` | `oklch(0.55 0.149 250)` | `oklch(0.70 0.135 250)` | 当前选中、主操作、@提及 |
| `signal` | `oklch(0.56 0.13 68)` | `oklch(0.76 0.13 74)` | **只用于「在等你」** —— 极度节省 |
| `on-duty` | `oklch(0.52 0.10 155)` | `oklch(0.72 0.11 155)` | 在岗 |

语义色与主色分家（Product register 要求）。`signal` 全界面只有一个用途：有事在等你拍板。看到它就一定要处理。

## Typography

**一个字族**，多个字重（Product register：产品 UI 不需要标题/正文配对）。

- UI：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif` —— 显式带 CJK，不靠系统兜底。
- 等宽：`ui-monospace, "SF Mono", Menlo, monospace` —— 工号、路径、id、时间。

**固定 rem 阶，比例 1.125**（不用 clamp —— 产品 UI 在固定 DPI 下看，流体标题在侧栏里只会更糟）：
`0.6875 / 0.75 / 0.8125 / 0.875 / 1 / 1.125 / 1.375 rem`

## Type scale

整体比第一版上调一档 —— 正文 15px、次要 13px、标签 12px，次要文字色压暗一档。
第一版正文 14px + 浅灰，在大屏上读起来像没做完。

## Spacing

固定刻度，不写裸 px（第一版到处是 11/14/18/22 —— 那不是节奏，是没定过）：
`--s-1: 4 · --s-2: 8 · --s-3: 12 · --s-4: 16 · --s-5: 22 · --s-6: 32`

## Layout

**三栏**（第一版是两栏，改了 —— 见 PRODUCT.md 参照那节）：

- **导航栏（68px，永远深底）**：公司标 + 消息/员工/设置 + 底部待办。选段，列表只显示那一段。
  第一版把「在等你 + 房间 + 员工」混成一长条，扫不出层级。
  它永远是深底，所以 `--nav-*` 那组 token **不跟主题翻转** —— 用会翻转的 `--signal` 在浅色下压深底只有 3.15:1（脚本抓到的）。
- **列表（304px）**：当前段的内容。
- **主区**：房间头 / transcript / 输入区。

**无气泡**：发言是平铺的记录行，`grid-template-columns: 名字 内容`。密度优先。

⚠️ **不给每条消息画分隔线。** 那会让 transcript 读成后台日志表格 —— 这是"像管理后台"最大的一个 tell。分组靠间距：换人说话时留一口气（`--s-4`），同一人接着说贴紧（2px）。

**响应式是结构性的**：< 760px 折成单栏 + 返回导航（不是流体字号）。

**z-index 语义阶**：`--z-sticky: 10 / --z-sheet: 30 / --z-toast: 50`。不写 999。

## Components

- **员工标识 / 头像**：32px 实心方块，**员工色底 + 首字**，色相由 id 推出（和名字颜色同源）。**不用真人照片** —— 员工是 agent。
  第一版是描边的字形单元格，没有分量，这是「太空」那条评价要解的一半。
- **消息块**：`头像列 32px | 名字行 + 正文`。连续发言隐藏名字行但**保持缩进对齐** —— 块结构靠对齐立住，不靠分隔线。
- **没填 key 的提醒**：消息段是一行（`还没填 DeepSeek key —— 员工不会回话` + 「去填」），完整表单只在设置段。必须看得见（不填就没人回话），但不该吃掉列表栏顶上四成 —— 第一版就是那样。
- **输入区**：一整块有边界的区域（`--panel` 底 + 白色输入框 + 底部一行提示与发送），focus 时描边加光环。第一版是一条细线，没有分量。
- **在场**：实心点=在岗、脉冲=在忙、空心点=不在工位。**都带文字标签**，不只靠颜色。
- **Ask 行**：中性面板（`--panel` + `--line` 边），**`signal` 只出现在 eyebrow 和"他没附方案"的提示上**。第一版铺了整块琥珀底加琥珀边，违反本文件自己写的"极度节省"。**禁止侧边色条**（绝对禁令）。
- **多问题的 Ask**：带编号 + `n/总数` 计数器 + 底部单一提交。**必须全部答完才能提交** —— 点一个选项就提交会吞掉其余答案（真用时第一个撞到的 bug）。编号在这里是合法的：顺序真的承载信息（还剩几个没答）。
- **方案正文**：`plan-review` 的 `detail` 要显示在一个独立框里。他让你拍板，你得看得见拍的是什么；声称拍板却没附方案时，明说出来。
- **过程**：员工这一轮读了什么、跑了什么命令，默认收起，一行入口"他做了 N 件事"。老板要的是"凭什么这么说"，不是一屏日志。
- **说话人名字上色**：每人一个稳定色相（由 id 推出，避开主色 250 与 signal 68–95 免得跟状态色抢读）。**只染名字，不染背景** —— 策略是 Restrained，多人群里全灰的名字扫不出谁是谁才是要解的问题。
- **未读分割线**：进房间时把"上次读到哪"固定成一条线（`以下是新消息`），之后的已读更新不移动它。
- **消息 hover 操作**：复制 / 引用，hover 或 focus 时才出现，不常驻占位。
- **⌘K**：房间 / 员工 / **消息全文** 三段。工作聊天软件没有搜索，历史一多就等于没有。
- **长对话分页**：一页 80 条，顶部一个"加载更早的"。全量渲染越来越卡，也没必要。
- 每个交互件都要有 default / hover / focus-visible / active / disabled / loading。
- **空状态要教会界面**，不是「暂无数据」。
- **没有模态框**。问答和拍板是消息。

## Signature：在等你的东西停在输入框上方

这个产品**唯一独有**的东西是：有个同事被你卡住了，只有你能解锁。飞书钉钉里没有任何东西是这样的 ——
所以 boldness 全花在这一处（`.dock`：signal 色上边框 + wash 底 + 入场动画），**别处保持安静**。

- **为什么停靠而不是排在消息流里**：它卡的是**你**。卡住你的东西该在你手边，不该被后面的消息刷走。
  第一版是流里的一张卡片，滚两下就找不到了。
- **一次只处理一件**，右上角标「还有 N 件」。三件堆在停靠区会占掉半屏，而且人本来也是一件一件答的。
- transcript 里只留一个发生点的标记（`XX 在这里问了你一件事 ↓ 在下面等你`），不刷一排。

## 横向溢出必须用脚本查

`apps/app/scripts/overflow.mjs`，和对比度脚本一起绑进 `npm run check`（`build` 会先跑）。

**根因是一类写法，不是个别 bug**：flex / grid 子项的 `min-width` 默认是 `auto`，长文本会把容器撑破；
而 grid 容器不写列定义时默认 `auto` = `max-content`，行宽由最长内容决定。

⚠️ **`overflow: hidden` 不是修，是遮。** 第一版我就那么"修"的 —— 视觉上不见了，实测仍然溢出 610px。
正确做法：flex 子项加 `min-width: 0`，grid 容器写 `grid-template-columns: minmax(0, 1fr)`。
脚本第一次跑就在同一类问题上又抓到 11 处。

## 对比度必须用脚本量，不许手算

`apps/app/scripts/contrast.mjs`，纯 Node 读 token 算，`npm run build` 会先跑它，不达标直接失败。

**为什么写死成一个文件**：在浏览器里手敲过四遍，四遍都错 —— 正则把 oklch 三个数当 RGB、读 canvas 的 `fillStyle` 回读值、没合成半透明前景、测量中途改 `data-theme` 然后跨渲染读值。每重写一遍就重新引入一个 bug。脚本本身有自检（`#767676` on 白必须是 4.54）。

新增界面元素时在 `PAIRS` 里加一行，别另起一套测法。

## Motion

150–250ms，`ease-out-quart`。只表达状态：新消息进入、ask 答完翻面、在忙的脉冲。
`prefers-reduced-motion: reduce` 下全部退化为瞬时或淡入。**不做载入编排** —— 产品是载入到任务里，不是载入给人看。
